SUPERTRUCK // ARCHITECTURE
10-MINUTE GPS PING — END TO END
WHAT HAPPENS AT EACH STEP
01
Flutter App
Driver Opens App
Flutter gets a JWT from Zitadel on login. On trip start, opens a WebSocket to ws://go:8080/ws/driver with Authorization: Bearer <JWT>.
02
Go Gateway
Auth + Trip Check
Validates JWT signature with the RSA public key (offline, 0.2ms). Extracts tenant_id and trip_id. Checks Redis: EXISTS {tenant}:trip_active:{trip}. No Postgres query.
03
Go Gateway
Ping Received
Every 10 minutes, Flutter sends { lat, lng, speed, heading, next_stop }. Go validates fields, checks rate limit (INCR {tenant}:rate_limit:{driver}), then forwards.
04
Redis Stream
XADD (not Pub/Sub)
Go publishes to a Redis Stream. Unlike Pub/Sub, Stream messages are durable — if NestJS is restarting, messages queue up and are processed when it comes back. Zero data loss.
05
Go Gateway
Instant Broadcast
Simultaneously, Go broadcasts the coordinates to any web dashboard clients watching this trip's "room". Dispatcher sees the truck move on the map immediately — before NestJS processes anything.
06
NestJS
XREADGROUP (async)
NestJS reads from the stream via consumer group nestjs-ingestion. Multiple NestJS replicas share the work. Each message is delivered to exactly one replica. Must XACK when done.
07
NestJS
Schema Switch + ETA
Sets search_path = tenant_abc. Runs full ETA engine: compares Live_ETA vs Appointment_Time, checks dwell thresholds, decides whether to write an eta_snapshot row.
08
PostgreSQL
Isolated Write
NestJS writes to the tenant's private schema: INSERT INTO tenant_abc.eta_snapshots. No other tenant can see or affect this data. Separate schema = hard isolation without separate databases.
⚡ WHY GO FOR WEBSOCKETS?
Go's goroutines start at 8KB — 50,000 connections = 400MB RAM. Node.js event loop would struggle with this many persistent connections.
Go's net/http handles keep-alive, read/write deadlines, and ping/pong at the OS level. Extremely low per-connection overhead.
If NestJS goes down for a deploy, Go keeps collecting pings. Redis Stream buffers them. Zero pings lost during NestJS restarts.
🔺 WHY NEST FOR BUSINESS LOGIC?
TypeORM + NestJS DI makes multi-tenant schema switching clean. One decorator, one service, all the ORM power your team already knows.
ETA engine, snapshot logic, dwell detection, issue creation — all of these need database access and complex business rules. NestJS is the right tool for that, not Go.
REST API, auth guards, Swagger docs, BullMQ jobs — all the heavyweight infrastructure lives in NestJS.
⚡
Go Gateway
The Real-Time Hub · port 8080
🔐
JWT Validation (Offline)
Validates RS256 signature using the RSA public key loaded at startup. No network call to Zitadel. Takes ~0.2ms. Checks tenant_id, trip_id, role custom claims.
🔴
Trip State Check (Redis only)
EXISTS {tenant}:trip_active:{trip} — single Redis lookup. NestJS sets this key on dispatch. Go never queries Postgres. This is why one Go pod handles 50k connections.
📡
WebSocket Management
Upgrades HTTP → WS. Maintains readPump + writePump goroutines per connection. Sends WS ping frames every 30s. Closes dead connections when pong times out after 60s.
⚖️
Rate Limiting
INCR {tenant}:rate_limit:{driver} with 60s expiry. Max 3 pings/min (configurable). Returns close code 4003 (retryable) when exceeded. Protects against buggy app ping loops.
📤
Redis Stream Publish
XADD Tracking:location_pings * payload {json}. Stream (not Pub/Sub) = durable. MAXLEN ~ 100000 prevents unbounded growth. NestJS uses XREADGROUP for at-least-once delivery.
📺
Dashboard Broadcast
Hub fans out coordinates to all web clients in the trip's "room". Dispatcher sees truck move instantly — before NestJS even reads the stream entry. Non-blocking: slow dashboards get dropped, not stalled.
✅
Ack + Health Endpoints
Sends { type: "ack", stream_id } back to Flutter. Exposes /health/live, /health/ready, /metrics for Kubernetes probes and monitoring.
Go does NOT:
✗ Query PostgreSQL directly
✗ Calculate ETAs or run business logic
✗ Know about multi-tenant schemas
✗ Write to tracking_logs or eta_snapshots
✗ Send customer notifications
🔺
NestJS Service
The Business Engine · port 3006
🚀
Trip Lifecycle Management
On dispatch: SET {tenant}:trip_active:{trip} {metadata} EX 86400 in Redis. This is the key Go watches. On trip end: DEL the key. Go automatically rejects new connections.
📨
Stream Consumer
XREADGROUP GROUP nestjs-ingestion consumer-1 COUNT 10 BLOCK 2000 STREAMS location_pings >. Multiple NestJS replicas share the load. Must XACK each message after processing.
🏢
Schema Switching
Reads tenant_id from the stream message. Sets search_path = tenant_abc on the DB connection. All subsequent queries go to that tenant's private schema. Other tenants are invisible.
🧮
ETA Engine
Compares revisedEta vs appointmentTime. Applies snapshot thresholds (10min shift → new snapshot). Sets isAtRisk = true when late by more than LATE_TOLERANCE_MINUTES.
📸
ETA Snapshot Writer
INSERT INTO {schema}.eta_snapshots when threshold crossed. Triggers: INITIAL_SET, TRAFFIC, PERIODIC (60min heartbeat), RISK_STATE_CHANGED, MANUAL_OVERRIDE.
⏱️
Dwell Detection
Tracks when a driver stops moving at a location. If same coordinates for > 2 hours → flags detention. Writes TrackingLog issue with type: DELAY for dispatcher resolution.
📋
REST API + WebHooks
Full CRUD for trips, stops, drivers. ETA override endpoint. Dispatcher notifications. Customer alerts. Swagger docs. All the heavyweight API surface that Go deliberately doesn't touch.
NestJS does NOT:
✗ Maintain WebSocket connections directly
✗ Handle the 50,000-connection fan-out
✗ Validate JWTs for every GPS ping
✗ Block a ping if it's temporarily down
✗ Know about WebSocket protocol details
REDIS KEY ARCHITECTURE

Every key is namespaced by {tenant_id} to guarantee complete isolation between companies. A bug in one tenant's code can never affect another's data.

STRING trip_active
{tenant_id}:trip_active:{trip_id}
Set byNestJS (on dispatch)
Read byGo (on WS connect)
TTL24 hours
OperationEXISTS (O(1))
The gatekeeper key. Go checks this on every new WebSocket connection. Without it, no driver can connect. Deleted by NestJS when trip ends or after 24h TTL (safety net).
STRING (JSON) last_loc
{tenant_id}:last_loc:{trip_id}
Set byGo (every ping)
Read byNestJS / Dashboard
TTL24 hours
OperationSET / GET
Cache for the driver's last known position. When the dispatcher opens the dashboard, they see the last location immediately without waiting for the next 10-minute ping.
COUNTER rate_limit
{tenant_id}:rate_limit:{driver_id}
Set byGo (every ping)
Read byGo (every ping)
TTL60 seconds
OperationINCR + EXPIRE
Fixed-window rate limiter. Scoped per-driver (not per-connection) so multiple connections can't bypass the limit. At 3/min limit, a 10-minute driver gets 30× headroom.
STREAM location_pings
Tracking:location_pings
Written byGo (XADD)
Read byNestJS (XREADGROUP)
Max length~100,000 entries
Consumer groupnestjs-ingestion
Why Stream not Pub/Sub? Pub/Sub drops messages if NestJS is offline. Streams are a persistent log — NestJS restarts and picks up every missed message. At-least-once delivery guaranteed.
PUB/SUB vs STREAMS — THE CRITICAL DIFFERENCE
❌ PUB/SUB (what NOT to use)
Go publishes a ping.
NestJS is restarting for a deploy.
Message is lost forever.

NestJS comes back online.
It never knew the ping happened.
ETA snapshot never written.
Driver arrives — no record in database.
✅ REDIS STREAMS (what we use)
Go publishes a ping via XADD.
NestJS is restarting for a deploy.
Message sits safely in the Stream.

NestJS comes back online.
Reads all pending entries with XREADGROUP.
Processes every missed ping in order.
XACK marks each as done.
